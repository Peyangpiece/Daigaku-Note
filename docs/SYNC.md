# Google ドライブでそろえる・iPad で単体で使う（SPEC の別紙）

パソコンが閉じていても iPad で使えるように、本人の Google ドライブを、パソコンと iPad の共通の置き場にする。
運営のサーバーは持たない（SPEC §5.2 の「運用コストゼロ」はそのまま）。ドライブに置くものは**すべて暗号化**し、鍵はパソコンと iPad だけが持つ（Google からも中身は読めない）。

## 1. 段階

| 段階                                  | 中身                                                                                                                                                                                                                                                              |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1. パソコン → ドライブ**（v0.22.0） | 設定 → データ で Google と連携する。パソコンのデータ（データベースの写し）と資料（PDF・画像・Word など）を暗号化してドライブへ送る（変わったものだけ）。暗号化したバックアップとしても働く                                                                        |
| 2. iPad のアプリ（読む・書く）        | App Store のアプリ（パソコンの画面を Capacitor で包む）。**2-1（v0.23.0）**：Google にログインし、パソコンの QR で鍵を受け取り、ドライブから読み込んで iPad に置く（§7）。**2-2**：iPad の中のデータでパソコンなしで開く。iPad で書いたものをドライブへ返す（§5） |
| 3. 両方向にそろえる                   | パソコンも iPad で書いたものを取り込む。同じものを両方で変えたときは、行ごとに新しいほう（§5）                                                                                                                                                                    |

## 2. Google との連携（パソコン）

- OAuth 2.0（インストール型のアプリの流れ）：既定のブラウザで Google のログインを開き、このパソコンの `127.0.0.1` の一時の口で受け取る（PKCE）。受け取った更新用のトークンは、パスワードと同じく OS の仕組みで暗号化して持つ（`secrets.js` の `cloud.google`）
- 権限は `drive.appdata`（ドライブの中の、このアプリだけの見えない領域。利用者のほかのファイルは見えない）と、アカウントを画面に出すための `openid email`
- クライアント ID は Google Cloud のコンソールで作る（プロジェクト `palette-note-514306`。`src/shared/google-client.js`。パソコン用は「デスクトップ アプリ」、iPad 用は「iOS」：バンドル ID `jp.daigakunote.ipad`・チーム ID `9G78U9XD92`）。同意画面は「外部」・テストの段階（テストユーザーに入れたアカウントだけが使える）。デスクトップのクライアントの秘密はリポジトリに置かず、Release が GitHub の Secrets（`GOOGLE_DESKTOP_CLIENT_SECRET`）から配布物に入れる（手元では同じ名前の環境変数。`main/cloud/client-secret.js`）。インストール型のアプリのクライアントの秘密は、配布物に入るので秘密として扱われない（Google の決まり）
- 「連携を外す」：トークンを取り消して消す。ドライブのデータは残す（「ドライブのデータを消す」で消せる）

## 3. 暗号化（`src/shared/vault.js`）

- 鍵：連携したときにパソコンで 32 バイトの乱数を作る（`secrets.js` の `cloud.key`）。ここから用途ごとの鍵を HMAC-SHA256 で作る：中身を包む鍵（`enc`）・名前を作る鍵（`name`）
- 包み方：`PNV1`（4 バイト）＋使い捨ての番号（24 バイト）＋ XChaCha20-Poly1305 の暗号文。付随データ（AAD）に置き場の名前を入れる（ほかの名前の中身とすり替えられない）
- 名前：資料は「名前を作る鍵で HMAC した中身のハッシュ」（同じ中身は 1 度だけ送る。Google から中身のハッシュは分からない）。データベース・目録は決まった名前（`db`・`manifest`）
- 鍵の計算（用途ごとの鍵・資料の名前・鍵の印・鍵の QR）は `src/shared/vault-keys.js`（@noble/hashes）。パソコンと iPad で同じものを使う
- 鍵を iPad に渡すのは、パソコンの画面に出す QR だけ（設定 → データ の「iPad に鍵を渡す」。中身は `palettenote-key:1:<鍵（base64url）>:<鍵の印>`。読み違えは鍵の印で見つける）。鍵がなければ、ドライブの中身は誰にも読めない

## 4. ドライブの中（appDataFolder）

| 名前       | 中身                                                                                                    |
| ---------- | ------------------------------------------------------------------------------------------------------- |
| `manifest` | 目録（暗号化した JSON）：版・送った時刻・送ったパソコン・データベースの名前・資料ごとの名前と大きさ     |
| `db`       | データベースの写し（`VACUUM INTO`。暗号化）。変わっていなければ送らない                                 |
| `f-<名前>` | 資料の中身（暗号化）。PDF は書き込みを描き込む前の元の PDF（注釈は別にデータベースにある。iPad で描く） |

- 送る順：資料 → データベース → 目録（目録は最後。途中で切れても、前の目録がそのまま使える）。目録から外れた資料は、目録を送ったあとに消す
- 自動で送る：連携しているあいだ、30 分ごとに変わったものだけ。「いま送る」でもすぐ送る

## 5. 両方向にそろえる（段階 2・3 の決まり）

- 行の番号はどの端末で作っても重ならない（ULID）。iPad で書いたものは「変更の記録」（どの表の、どの行を、いつ、どう変えたか）としてドライブに置き、パソコンが取り込む
- 同じ行を両方で変えたときは、変えた時刻の新しいほうを残す。消したことも記録し、両方から消す
- 資料の中身は、ハッシュの名前なので重ならない

## 6. iPad 単体でできないこと

- manabo からの資料の自動取得（ブラウザを自動で動かす仕組みが iPad では動かない）。パソコンが取得してドライブに置いた分までを使う
- Claude Code での問題作成、パソコンのフォルダの登録・見張り

## 7. iPad のアプリの読み込み（段階 2-1。`ipad/src/cloud/`）

- Google のログイン：iOS のクライアント（秘密なし）で PKCE。Safari の画面（@capacitor/browser）で開き、`com.googleusercontent.apps.…:/oauth2redirect` でアプリに戻る（@capacitor/app の appUrlOpen。Info.plist の CFBundleURLTypes）。appDataFolder は同じプロジェクトのクライアントで共通なので、パソコンが置いたものが見える
- 通信：まず fetch。ブラウザの決まり（CORS）で止められたら、アプリの通信（CapacitorHttp）で送り直す
- 読み込み（`pull.js`）：目録を読み、まだないもの・データベースが変わったときはデータベースを読む。開けるか確かめてから、**暗号化したまま** アプリの書類の場所（@capacitor/filesystem の Data/drive/）に置く。目録を置き換えてから、外れたものを消す
- 覚えるもの（アプリの中の localStorage）：更新用のトークン・メールアドレス・鍵・鍵の印。「この iPad から外す」で、トークンを取り消し、鍵と読み込んだものを消す
